Git · version control

What is Git?

core Git is a distributed version control system that tracks changes in your files and coordinates work among multiple people. It’s the backbone of modern software development — used by millions to manage source code, collaborate, and keep history.

Key features: snapshots, branching, merging, staging area, distributed workflows, and everyone has a full copy of the repository.

Created by Linus Torvalds in 2005, Git is free, open-source, and incredibly fast.

Why use Git?

Track everything — every change, who made it, and when.
Branch & merge — experiment without breaking the main code.
Collaborate — multiple developers work simultaneously.
Revert — go back to any previous state in seconds.

How to use Git (basics)

Below are the most common commands to get you started. All commands are run in your terminal (or Git Bash on Windows).

1. Install & configure

# check if Git is installed
git --version

# set your identity (required for commits)
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

2. Start a new repo or clone

# create a new repository in the current folder
git init

# clone an existing repository from remote
git clone https://github.com/user/repo.git

3. Basic workflow (add, commit, push)

# see what's changed
git status

# stage changes (add files to the snapshot)
git add filename # stage a specific file
git add . # stage all changes

# commit — save a permanent snapshot
git commit -m "meaningful message"

# push to remote (like GitHub)
git push origin main # or 'master' for older repos

4. Branching & merging

# list branches
git branch

# create a new branch
git branch feature-xyz

# switch to that branch
git checkout feature-xyz # or: git switch feature-xyz

# merge feature-xyz into main
git checkout main
git merge feature-xyz

5. Stay up to date

# download changes from remote (but don't merge)
git fetch

# download AND merge into your current branch
git pull origin main

Handy extras

git log — view commit history
git reset — undo stages / commits
git diff — see changes before staging
git tag — mark releases
git stash — save uncommitted work temporarily
git remote -v — list remotes

.gitignore — create a .gitignore file to exclude temporary files, logs, node_modules, etc. from version control.

# .gitignore example
node_modules/
.env
*.log
dist/

Ready to go deeper? Explore git branch --help, interactive tutorials, or the official Git documentation.

Pro tip: Use git log --oneline --graph for a pretty commit tree.
